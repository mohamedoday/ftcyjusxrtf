01

Code, mathematics and verifiable tasks

For DeepSeek, define a result you can verify. In programming, provide inputs, outputs and constraints; in mathematics, state the assumptions and how the answer can be checked. If you need a specific format, such as a table or JSON, make that requirement explicit.

02

Example: verifiable data conversion to JSON

Convert the records to a JSON object with exactly one key, ids. Its value must be an array of unique integers in ascending order. Ignore empty records and records that are not integers. Return only JSON, without Markdown or commentary.
Input records: ["10", "2", "2", "", "abc", "-1"]
Expected result for validation: {"ids":[-1,2,10]}

03

Check structure and meaning separately

First check that a standard JSON parser can read the response. Then compare ids with [-1, 2, 10]: 2 must not appear twice, 10 must follow 2, and strings or empty values must not appear in the array. Valid JSON syntax alone does not establish a correct answer.

For model-generated code, add separate cases: empty input gives an empty array; repeated identical values give one number; negative values keep their correct numeric order. Run checks in your own environment and record the language and runtime version.

The expected JSON is derived directly from the input. It is a reference answer for the exercise, not a claim that a particular DeepSeek version has passed a test.

04

If the response is blank, truncated or misformatted

In an ordinary chat, explicitly request JSON and show a short example of the desired structure. If the response is truncated, reduce the task or split the input into independent parts. Do not concatenate incomplete JSON fragments without validation.

For an API integration, prompt wording alone does not enable JSON Output: use DeepSeek’s response_format parameter, mention JSON in the message and check the output length limit. Handle blank responses and parsing failures separately. Chat and API capabilities can differ.

05

How to evaluate the result

Do not judge a prompt solely by the length of its reasoning. Run proposed code on normal and edge cases, and verify calculations independently. Match the DeepSeek version and operating mode to the file's instructions rather than assuming every file works the same way.
